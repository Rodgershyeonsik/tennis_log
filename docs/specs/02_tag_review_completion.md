# 02. 태그 확인 완료 개선 (평가 없음)

```
작업 유형: 개선 (기존 기능 변경)
영향 받는 명세: 01
선행 작업: 없음
```

공통 규칙, 기술 스택, 데이터 모델은 루트의 `CLAUDE.md`를 따른다. 이 문서는 `01_journal_entry.md`로 만든 **2단계(태그·평가 확인)와 자동 평가 추천을 고치는** 작업이다. CLAUDE.md의 "명세에 없는 기존 기능은 수정하지 않는다"에 대해, 이 문서에 적힌 범위의 수정은 허가된 것으로 본다.

## 1. 배경

- 평가 없는 단순 메모가 많은데, 지금은 "평가 없음"을 **확정할 방법이 없다.** `evaluation = null`이면 "사용자가 보고 평가할 게 없다고 정한 것"과 "아직 아무도 안 본 것"이 구분되지 않는다.
- 2단계에서 점선 추천을 그대로 두고 **완료**를 누를 수 있어서, 확인 완료된 일지 안에도 미확정 태그·평가가 남는다.
- 다음 작업(`03_memo_search_stats.md`)의 조회·통계는 **확인 완료 일지의 확정값만** 쓴다. 이 작업으로 "확인 완료 일지에는 점선(suggested)이 하나도 없다"를 보장한다.

## 2. 범위

**구현할 것**

- 평가 값에 `none`(평가 없음) 추가, 마이그레이션
- 자동 평가 추천: 키워드가 없으면 `none` 추천
- 저장 시 적용 규칙: `none` 확정의 예외 처리
- 2단계 평가 버튼 4개(잘함 / 못함 / 물음표 / 없음)
- 완료 버튼의 확인 시트
- `01_journal_entry.md`, `CLAUDE.md` 갱신

**구현하지 않을 것**

- 조회·통계 화면 (03에서)
- 태그 인식 규칙(태그 알고리즘) 변경
- 메인 화면 진행 단계 배지 로직 변경 (기존 그대로)

## 3. 데이터 모델 변경

**memos.evaluation**: `good / bad / question / none` (nullable)

| 상태          | evaluation               | evaluationStatus | 뜻                              |
| ------------- | ------------------------ | ---------------- | ------------------------------- |
| 고르지 않음   | null                     | null             | 추천도 확정도 없음              |
| 추천 (점선)   | good/bad/question/none   | suggested        | 자동 추천, 사용자가 아직 안 봄  |
| 확정          | good/bad/question/none   | confirmed        | 사용자가 확정                   |

- `none` = **평가 없음.** null(고르지 않음)과 다르다.
- "evaluation이 null이면 evaluationStatus도 null" 규칙은 그대로다.
- enum 값 **추가**라 기존 행은 안전하다. 그래도 아래 마이그레이션 때문에 `schemaVersion`을 올린다.

**불변식 (이 작업 이후)**: `tagReviewed = true`인 세션은

- 모든 메모의 evaluationStatus가 confirmed다(evaluation이 null인 메모가 없다).
- memoTags에 status = suggested인 행이 없다.

### 마이그레이션

순서대로 실행한다(한 트랜잭션).

1. **점선이 남은 확인 완료 일지 되돌리기**: tagReviewed = true인 세션 중, 메모에 evaluationStatus = suggested가 있거나 memoTags에 status = suggested가 있는 세션 → tagReviewed = false. (사용자가 2단계를 다시 거쳐 직접 고르게 한다.)
2. **확인 완료 일지의 빈 평가**: tagReviewed = true인 세션의 메모 중 evaluation이 null인 것 → evaluation = none, evaluationStatus = confirmed. (사용자가 보고 비워 둔 것이므로 평가 없음으로 본다.)
3. **확인 전 일지의 빈 평가**: tagReviewed = false인 세션의 메모 중 evaluation이 null이고 lastTaggedContent가 null이 아닌 것(추천을 한 번이라도 돌린 메모) → **평가 추천 로직을 그 메모 내용으로 다시 돌려서**, 결과가 none이면 evaluation = none, evaluationStatus = suggested. 결과가 null(판단 보류)이면 그대로 둔다.
   - lastTaggedContent가 null인 메모(작성 중 일지에서 아직 저장 버튼을 안 거친 메모)는 건드리지 않는다. 다음 저장 때 추천이 돈다.
   - 평가 추천은 순수 Dart 상수 기반이라 마이그레이션 안에서 호출할 수 있다. 태그 추천은 다시 돌리지 않는다.

마이그레이션 테스트를 작성한다(각 단계별로 전후 데이터 확인).

## 4. 자동 평가 추천 변경

키워드 표와 매칭 방식(포함 여부)은 그대로다. 결과만 바뀐다.

| 매칭 결과                              | 추천               |
| -------------------------------------- | ------------------ |
| question 키워드가 있음                 | question           |
| good만 있음                            | good               |
| bad만 있음                             | bad                |
| good과 bad가 둘 다 있음 (question 없음) | **null** (판단 보류) |
| **아무 키워드도 없음**                 | **none**           |

- 판단 보류를 none으로 만들지 않는 이유: 잘함·못함을 모두 언급한 메모를 "평가할 게 없다"로 밀어 넣으면 안 된다. 사용자가 직접 고르게 둔다.

### 저장 시 적용 규칙 (AutoTagApplier)

내용이 lastTaggedContent와 다른 메모만 다시 처리하는 것, manual·rejected 태그를 건드리지 않는 것은 그대로다. 평가 부분만 아래로 바꾼다.

| 기존 평가                              | 새 추천 결과                 | 처리                                   |
| -------------------------------------- | ---------------------------- | -------------------------------------- |
| confirmed good / bad / question        | (결과와 상관없음)            | **유지** (기존과 같음)                 |
| **confirmed none**                     | good / bad / question        | **새 결과로 교체**, status = suggested |
| confirmed none                         | none 또는 null(판단 보류)    | 유지                                   |
| null 또는 suggested                    | (결과와 상관없음)            | 새 결과로 교체 (null이면 비움)         |

- confirmed none만 예외인 이유: 평가 없음은 "그 내용엔 평가할 게 없다"는 판단이라, 내용에 평가 키워드가 새로 생기면 다시 볼 만하다. 확정된 잘함·못함·물음표는 사용자의 판단이라 계속 지킨다.
- 다시 처리한 메모가 있으면 tagReviewed = false로 되돌리는 규칙은 그대로다.

### 단위 테스트 (추가·변경)

기존 `01_journal_entry.md` 6번 테스트는 모두 유지하되, 평가 기대값을 아래처럼 바꾼다.

| 메모                                                         | 기대 결과                       |
| ------------------------------------------------------------ | ------------------------------- |
| 세컨 토스 침착하게 올리니까 잘 들어감                        | 평가 **none** 추천              |
| 포인트 몇 개 땀                                              | #포핸드 없음, 평가 none 추천    |
| 서브는 잘됨 근데 리턴은 안됨                                 | 평가 추천 **null** (판단 보류)  |
| (confirmed good인 메모를 "안 됨ㅠ"로 수정 후 저장)           | good 확정 유지 (기존)           |
| (confirmed none인 메모를 "오늘 서브 개굿"으로 수정 후 저장)  | good 추천                       |
| (confirmed none인 메모를 "토스 높게"로 수정 후 저장)         | none 확정 유지                  |
| (confirmed none인 메모를 "서브는 잘됨 근데 리턴은 안됨"으로) | none 확정 유지                  |
| (suggested bad인 메모를 "토스 높게"로 수정 후 저장)          | none 추천                       |
| (suggested none인 메모를 "백발리 안 됨ㅠ"로 수정 후 저장)    | bad 추천                        |

그 밖에 기대 결과에 평가가 적혀 있지 않은 기존 케이스는 태그만 검증하던 것이므로 그대로 둔다.

## 5. 2단계 화면 변경

### 평가 버튼 4개

- 순서: 잘함 / 못함 / 물음표 / **없음**.
- 없음 아이콘: Material `remove_circle_outline`(고르지 않음 상태), `remove_circle`(추천·확정 상태). 이모지는 쓰지 않는다(01 규칙 그대로).
- 없음의 색은 **중립 회색 계열**. 확정 상태의 면도 회색 계열로 채운다. 고르지 않음(흐린 회색 윤곽선 + 실선 테두리 + 흰 면)과 확정(테두리 없이 회색 면 + 채운 아이콘)이 확실히 구분되게 한다.
- 크기·둥근 정도·터치 영역(48dp)·세 가지 모습(고르지 않음 / 추천 점선 / 확정 면)은 기존 3개와 같은 규칙(`ChipMetrics`)을 따른다. 버튼이 4개가 돼도 좁은 폭(약 400px)에서 한 줄에 들어가야 한다.
- 동작도 같다: 추천을 탭하면 확정, 다른 버튼을 탭하면 그 평가로 확정, 확정된 버튼을 다시 탭하면 고르지 않음(null).

### 모두 확인

- 기존 그대로: suggested 태그와 suggested 평가(none 포함)를 모두 confirmed로 바꾼다.
- 고르지 않음(null) 평가는 건드리지 않는다.

### 완료 버튼

- 누를 때 아래 중 하나라도 있으면 **확인 시트**를 띄운다.
  - suggested 태그
  - suggested 평가
  - 평가를 고르지 않은(null) 메모
- 시트 문구(해당하는 줄만 보여준다):
  - "추천 태그 N개, 추천 평가 M개가 아직 확정되지 않았어요." (N 또는 M이 0이면 그 부분 생략)
  - "평가를 고르지 않은 메모 K개는 '없음'으로 확정돼요."
- 버튼: **확정하고 완료** / **돌아가기**.
  - 확정하고 완료: suggested 태그 → confirmed, suggested 평가 → confirmed, null 평가 → none/confirmed, tagReviewed = true, 메인으로.
  - 돌아가기: 시트만 닫는다.
- 해당하는 게 없으면 시트 없이 바로 완료(tagReviewed = true, 메인으로).
- 이렇게 해서 3번의 불변식을 지킨다.

안내 문구("추천 태그/평가는 점선으로 표시돼요. 터치하면 태그/평가가 확정돼요.")는 그대로 둔다.

## 6. 문서 갱신

- `CLAUDE.md` 데이터 모델:
  - memos.evaluation 값에 `none` 추가, 위 상태 표의 요지(null = 고르지 않음, none = 평가 없음).
  - sessions.tagReviewed 설명에 3번의 불변식 추가.
- `01_journal_entry.md`:
  - 5번: 평가 아이콘 3개 → 4개, 완료 버튼의 확인 시트.
  - 6번: 평가 추천 표와 "여러 평가가 동시에 매칭되면" 규칙에 none·판단 보류 반영, 저장 시 적용 규칙의 confirmed none 예외, 단위 테스트 기대값.
- 두 문서의 해당 부분에 "02에서 변경"이라고 짧게 표시한다.

## 7. 구현 단계

1. **데이터**: enum에 `none` 추가, `schemaVersion` 올림, 3번 마이그레이션과 테스트. 앱(웹)을 열어 기존 데이터가 보존되는지 확인.
2. **평가 추천 엔진**: 4번 결과 표 반영, 단위 테스트 갱신·추가.
3. **저장 시 적용 규칙**: confirmed none 예외, 테스트 추가.
4. **2단계 화면**: 평가 버튼 4개, 완료 확인 시트.
5. **점검**: 웹에서 다음을 확인하고 결과를 알려줄 것.
   - 키워드 없는 메모를 저장 → 2단계에서 없음이 점선으로 보임 → 모두 확인 → 완료.
   - 점선을 남긴 채 완료 → 시트 → 돌아가기 / 확정하고 완료.
   - 확정된 없음 메모를 1단계에서 "개굿"을 넣어 고침 → 저장 → 태그 확인 전 배지, 2단계에서 잘함 점선.
   - 마이그레이션 전부터 있던 확인 완료 일지의 상태.
   - 마지막으로 6번 문서 갱신.
