# 03. 메모 조회와 태그 통계

```
작업 유형: 기능 추가
영향 받는 명세: 01 (메인 화면, 라우터)
선행 작업: 02
```

공통 규칙, 기술 스택, 데이터 모델은 루트의 `CLAUDE.md`를 따른다. 이 문서는 이번 작업의 범위와 화면, 동작만 다룬다.

**선행 작업**: `02_tag_review_completion.md`가 끝나 있어야 한다. 이 문서는 "확인 완료 일지에는 점선(suggested)이 없다"는 02의 불변식과 평가 값 `none`을 전제로 한다.

## 1. 범위

**구현할 것**

- 하단 내비게이션 탭(일지 / 조회)과 그에 맞춘 메인 화면 조정
- 조회 화면: 필터 바, 필터 시트, 메모 탭, 태그 통계 탭
- 세션 상세 시트(읽기 전용)
- 조회 쿼리 리포지토리, 집계 로직(순수 Dart) + 단위 테스트

**구현하지 않을 것**

- 조회 화면에서의 **모든 편집**(메모, 태그, 평가, 세션). 조회 화면은 읽기 전용이다.
- 세션 상세 시트에서 일지 작성 화면으로 가는 진입점
- 조회 조건 저장(프리셋)
- 마지막 식사 등 이 문서에 없는 필터
- 차트, 내보내기
- 태그 관리, 장비, 플레이어 탭 (나중에 탭으로 추가할 수 있게 구조만 열어 둔다)

### 이 기능으로 할 수 있어야 하는 조회 (점검 기준)

1. 최근 10개 세션 중 잘함 메모를 본문 전체로 모아 보고, 태그별 건수와 평가 현황을 확인한다.
2. 최근 3개월 메모 중 못함이 가장 많은 **기술** 태그를 찾는다.
3. 특정 태그가 달린 메모를 기간 지정 또는 전체로 조회하고, 세션 날짜 기준 최신순·오래된순으로 정렬한다.

## 2. 하단 내비게이션

- go_router의 `StatefulShellRoute`로 탭 두 개를 둔다: **일지**(`/`) / **조회**(`/search`).
- Material 3 `NavigationBar`. 아이콘과 라벨을 항상 표시한다. 물결·음영 효과는 기존 테마 규칙대로 끈다(`NavigationBar`의 overlay도 투명).
- **탭을 바꿔도 각 탭의 상태가 유지된다**(조회 필터, 결과 스크롤 위치, 메모/통계 탭 선택). 앱을 다시 시작하면 조회 필터는 초기값으로 돌아간다.
- 일지 작성(`/journal/new`, `/journal/:id`)과 태그 확인(`/journal/:id/tags`)은 **셸 밖**의 전체 화면 라우트다. 이 화면들에서는 내비게이션 바가 보이지 않는다. 기존 경로와 동작은 바꾸지 않는다.
- Android 뒤로가기: 조회 탭에서는 일지 탭으로 이동, 일지 탭에서는 기본 동작(앱 종료).
- 나중에 태그 관리·장비·플레이어 탭이 추가된다. 탭 목록을 한곳에서 정의해 탭 추가가 쉬운 구조로 만든다.

### 메인 화면(일지 탭) 조정

이 항목은 기존 메인 화면 수정을 허가한다.

- 하단에 고정돼 있던 **새 일지 쓰기** 버튼을 없애고, **앱바 오른쪽에 아이콘 + "새 일지" 글자 버튼**으로 둔다. 화면 아래에는 내비게이션 바만 남는다.
- 그 밖의 메인 동작(목록, 배지, 밀어서 삭제, 실행 취소)은 그대로다. 실행 취소 스낵바가 내비게이션 바를 가리지 않는지 확인한다.

## 3. 조회 대상 (모든 조회에 공통)

- **세션 status = complete 이고 tagReviewed = true인 세션**의 메모만 조회한다.
  - 작성 중 일지와 태그 확인 전 일지는 빠진다.
  - 메인 목록의 태그 버튼으로 작성 중 일지의 2단계를 완료하면 tagReviewed만 true가 될 수 있다. 이런 일지도 status가 complete가 아니므로 빠진다(장소 스냅샷도 없다).
- 태그는 memoTags.status = **confirmed**인 것만 센다. 평가도 evaluationStatus = confirmed인 값만 쓴다. 02의 불변식상 대상 세션에는 다른 상태가 없어야 하지만, 쿼리에서도 방어적으로 조건을 건다.
- 결과 위에 안내 한 줄: **"확인 완료 전 일지 N개는 빠졌어요"**
  - N = 메모가 1개 이상 있지만 조회 대상이 아닌 세션 수. 작성 중 일지와 태그 확인 전 일지를 모두 센다. 범위가 기간이면 그 기간 안에서, 그 밖(전체, 최근 N세션)이면 전체에서 센다.
  - N이 0이면 숨긴다. 눌러도 아무 동작이 없다.

## 4. 필터

**모든 필터의 기본값은 "제한 없음"이다.** 범위의 기본값은 전체다.

필터 그룹 사이는 AND, 한 그룹 안의 여러 선택은 OR이다(태그만 OR/AND를 고를 수 있다).

### 범위 (하나만 선택)

- **전체** (기본)
- **기간**: 프리셋 1개월 / 3개월 / 6개월 / 올해, 또는 **직접 지정**(시작일 ~ 종료일, 날짜 범위 선택기).
  - 세션 date 기준. 양 끝 날짜 포함.
  - "최근 N개월" = 오늘로부터 N개월 전 같은 날짜 ~ 오늘. 예: 2026-10-25 기준 3개월 → 2026-07-25 ~ 2026-10-25. 그 달에 같은 날짜가 없으면 그 달 말일(5/31 기준 1개월 → 4/30).
  - 올해 = 올해 1월 1일 ~ 오늘.
- **최근 N세션**: N은 스테퍼(1~50, 기본 10).
  - 조회 대상 세션에 **세션 단위 필터(세션 유형, 장소, 컨디션, 큐 적용)를 먼저 적용**한 뒤, 날짜 최신순(같은 날이면 시작 시각 늦은 순, 그다음 id 큰 순)으로 N개를 고른다.
  - 메모 단위 필터(평가, 태그)는 그 N개 세션의 메모 안에서 적용한다.

### 평가 (여러 개)

잘함 / 못함 / 물음표 / 평가 없음(`none`).

### 태그 (여러 개)

- 태그 선택 시트: 상단 검색(부분 일치) + 카테고리별 목록. 보관된(isArchived) 태그는 목록에서 뺀다. 검색 시트의 키보드 대응은 01의 규칙(남는 높이에 맞춰 목록 줄이기)을 따른다.
- 부모 태그를 고르면 **자손 태그가 붙은 메모도 포함**한다(자식의 자식까지 모든 단계).
- 여러 개를 골랐을 때 매칭 방식: **하나라도**(OR, 기본) / **모두**(AND). AND일 때 각 선택 태그의 조건은 "그 태그 또는 그 자손이 붙어 있음"이다.

### 세션 유형 (여러 개)

게임 / 레슨 / 랠리·연습.

### 장소 (세 그룹, 그룹 사이 AND)

- **코트 표면**(여러 개): 하드 / 인조잔디 / 클레이 / 기타 — `surfaceSnapshot` 기준.
- **실내·야외**(여러 개): 실내 / 야외 — `isIndoorSnapshot` 기준.
- **특정 장소**(여러 개): 장소 선택 시트(01의 장소 선택 시트와 같은 검색 방식, 선택 시 시트를 닫지 않고 여러 개 체크) — `placeId` 기준.
- 조회 대상은 모두 저장을 마친 세션이라 스냅샷이 있다.

### 컨디션 (여러 개)

별로 / 쏘쏘 / 굿 / **기록 없음**(conditionScore = null).

### 큐 적용 (여러 개)

됨 / 일부 / 안 됨 / **기록 없음**(cueApplied = null. 큐가 없거나 적용 여부를 안 고른 세션, 레슨 세션 포함).

### 필터 바 (조회 화면 상단, 가로 스크롤 한 줄)

- 맨 앞에 **범위 칩**(항상 표시. 예: "전체", "최근 3개월", "최근 10세션", "26/7/1 – 26/9/30").
- 이어서 **걸린 필터마다 칩 하나**(예: "못함", "서브", "클레이"). 칩의 x로 그 필터만 해제한다. 태그가 여러 개고 AND면 "서브 + 몸열림"처럼 한 칩으로 묶는다.
- 끝에 **필터 버튼**(아이콘 + 걸린 필터 개수). 범위 칩이나 필터 버튼을 누르면 필터 시트가 열린다.

### 필터 시트

- 위에서부터: 범위 / 평가 / 태그 / 세션 유형 / 장소 / 컨디션 / 큐 적용. 칩은 01의 칩 스타일을 따른다.
- 시트 안의 변경은 **임시 상태**다. 하단 **결과 보기 N**(N = 현재 시트 조건의 메모 수, 바뀔 때마다 갱신)을 눌러야 적용된다. 바깥을 눌러 닫으면 적용하지 않는다.
- **초기화**: 시트 안의 모든 조건을 기본값으로 되돌린다(적용은 결과 보기에서).
- 시트는 위로 끌면 전체 높이까지 펼쳐진다. 키보드가 올라오는 하위 시트(태그·장소 선택)는 01의 키보드 규칙을 따른다.

## 5. 조회 화면

- 상단 바 제목 "조회". 탭 화면이라 뒤로가기 버튼은 없다.
- 그 아래 필터 바, 3번의 안내 줄, 결과 탭 두 개: **메모 N** / **태그 통계**.
- 메모 탭과 태그 통계 탭은 **같은 결과 메모 집합**을 쓴다(모든 필터가 똑같이 적용된다).
- 결과는 DB 변경을 따라 갱신된다(drift watch). 일지 탭에서 일지를 고치거나 지우고 돌아오면 반영돼 있어야 한다.

### 메모 탭

**요약줄 (최상단, 가로 스크롤)**

- 결과 메모에 **실제로 붙은 태그**마다 칩 하나. 부모 합산은 하지 않는다(합산은 통계 탭에서만).
- 칩 내용: 태그명, 건수, 평가별 건수. 예: `서브 7 · 👍0 👎7`. 평가는 잘함·못함·물음표·없음 아이콘(02의 아이콘을 작게)과 숫자로 쓰고, 0인 평가는 생략한다.
- 순서: 건수 많은 순, 같으면 태그 이름 순.
- 칩을 누르면 **태그 필터가 그 태그 하나로 바뀐다**(다른 필터는 유지, 태그 매칭 방식은 OR로).
- "건"은 메모 수다. 평가별 건수의 합은 그 태그의 건수와 같다(대상 메모는 모두 확정 평가가 있다).

**정렬** (요약줄 아래 오른쪽): 최신순(기본) / 오래된순.

- 세션 date → 같은 날이면 startMinutes → 세션 id 순으로 세션을 정렬한다(최신순이면 모두 내림차순).
- 같은 세션 안의 메모는 정렬 방향과 상관없이 항상 orderIndex 오름차순(쓴 순서).

**메모 카드**

- 위 줄: 세션 날짜(짧은 형식 `26/10/13 화`) · 장소 이름(`placeNameSnapshot`), 오른쪽 끝에 `›` 표시.
- 메모 본문 **전체**(줄임 없음).
- 아래 줄: 확정 태그 칩(2단계의 확정 모양, 표시용), 오른쪽 끝에 평가 아이콘 하나(확정 모양, 표시용). 평가가 없음이면 아이콘을 생략한다.
- 태그 칩과 평가 아이콘은 **눌러도 아무 동작이 없다**(버튼이 아니라 표시).
- **카드 어디를 눌러도 세션 상세 시트**가 열린다(7번).
- 긴 목록을 위해 지연 생성 리스트를 쓴다.

**결과가 없을 때**: "조건에 맞는 메모가 없어요." + **필터 초기화** 버튼(모든 필터를 기본값으로 즉시 적용).

### 태그 통계 탭

**카테고리 칩** (한 줄, 하나만 선택): 전체(기본) / 기술 / 폼 / 풋워크 / 상황 / 몸 / 컨디션 요인. 카테고리 표기는 기존 2단계 "새 태그 만들기"의 표기와 맞춘다.

**정렬**: 건수순(기본) / 잘함순 / 못함순 / 물음표순. 기준 값이 같으면 총 건수 많은 순, 그다음 이름 순.

**행 하나 = 태그 하나**

- 태그명, 총 N건, 아래에 평가별 건수(잘함 / 못함 / 물음표 / 없음. 행끼리 줄이 맞도록 0도 흐리게 표시).
- 결과에 한 번도 등장하지 않은 태그는 보이지 않는다.

**부모·자식 태그**

- 최상위 행은 **부모가 없는 태그**다. 자식 태그는 최상위에 따로 나오지 않고 부모 아래에만 나온다.
- 부모 행의 건수 = 자기 자신 **또는** 자손 태그가 붙은 메모 수. **같은 메모는 한 번만** 센다. 평가별 건수도 같은 메모 집합으로 센다.
- 자식이 결과에 등장한 부모 행에는 펼침 화살표를 둔다. 펼치면 "직접 N"(부모 태그 자체가 붙은 메모 수)과 각 자식 행(자식 자체의 건수와 평가별 건수)을 보여준다. 자식 행도 같은 정렬 기준을 따른다.
- 부모 자신은 붙은 적 없고 자식만 등장해도 부모 행은 나온다(직접 0).
- 카테고리 칩은 최상위 태그의 카테고리로 거른다.

**행을 누르면** 태그 필터가 그 태그 하나로 바뀌고(다른 필터 유지, OR) **메모 탭으로 이동**한다. 부모 행이면 자손 포함 조회가 된다. 펼침 화살표는 별도의 48dp 터치 영역으로, 펼치기만 한다.

**예시 2의 사용법**: 범위 3개월 + 평가 못함 + 통계 탭 + 기술 + 건수순. 맨 위 행이 답이다. (평가 필터 없이 못함순으로 봐도 된다.)

  - 테스트는 `test/` 아래 같은 경로에 둔다.
- **SearchFilter**: freezed 모델(범위, 평가, 태그와 매칭 방식, 세션 유형, 표면, 실내외, 장소, 컨디션, 큐 적용).
- **리포지토리**: 필터를 받아 결과 메모 목록을 Stream으로 돌려준다. 각 항목은 메모(id, 내용, orderIndex, 확정 평가), 세션 요약(id, date, startMinutes, placeNameSnapshot), 확정 태그 id 목록이다. 3번 안내 줄의 N도 같은 리포지토리에서 제공한다.
  - 무엇을 SQL로 거르고 무엇을 Dart로 거를지는 구현 판단이다. 다만 결과는 아래 테스트를 통과해야 한다.
  - drift 생성 클래스는 `@riverpod` 반환 타입에 쓸 수 없다(CLAUDE.md). 조회 결과는 freezed 도메인 모델로 감싸거나, 프로바이더를 손으로 선언한다.
- **집계 로직은 UI와 분리한 순수 Dart 클래스**로 만든다. 입력: 결과 메모 목록 + 태그 사전(id, 이름, 카테고리, 부모). 출력: 요약줄 항목, 통계 행(계층 포함), 정렬.
- 태그 필터의 자손 포함, 최근 N세션 선택, 기간 계산도 순수 함수로 두고 테스트한다.
- 날짜 비교는 `sessions.date`가 로컬 자정으로 저장돼 있다는 CLAUDE.md 규칙을 따른다.

## 7. 세션 상세 시트 (읽기 전용)

메모 카드를 누르면 열린다. 위로 끌면 전체 높이까지 펼쳐진다(처음 높이는 화면의 약 70%).

- **머리**: 날짜(긴 형식 `2026년 10월 12일 월요일`), 시간 `20:00 – 22:00`(시작·종료가 없으면 생략), 오른쪽에 작게 "읽기 전용".
- **기본 정보**: 세션 유형 · 장소 이름(스냅샷) · 실내/야외 · 코트 표면.
- **컨디션**, **마지막 식사**: 값, 없으면 "기록 없음".
- **큐**(레슨이 아니고 큐가 있을 때만): 큐 텍스트, 적용 결과(됨/일부/안 됨, 없으면 "기록 없음").
- **스코어**(게임일 때만): 01의 스코어 표시 방식(유형별로 묶음, 이긴 경기 강조)을 읽기 전용으로 쓴다. 기록이 없으면 "스코어 기록 없음".
- **메모 전체**(orderIndex 순): 각 메모의 본문, 확정 태그, 평가.
  - **누른 메모는 강조**하고, 시트가 열릴 때 그 메모가 보이도록 스크롤한다.
- 편집으로 가는 버튼은 두지 않는다. 모든 요소가 눌러도 아무 동작이 없다.
- 01에서 만든 표시용 위젯(스코어 칩 등)을 재사용한다. 재사용하려면 기존 위젯 수정이 필요해 보이면 먼저 물어본다.

## 9. 구현 단계

1. **하단 내비게이션**: `StatefulShellRoute`로 일지/조회 탭, 빈 조회 화면, 앱바의 새 일지 버튼, Android 뒤로가기. 기존 경로(작성, 태그 확인)가 그대로 동작하고 그 화면들에서 내비게이션 바가 보이지 않는지 확인.
2. **조회 도메인과 데이터**: SearchFilter, 리포지토리 쿼리, 범위 계산·자손 포함·집계 순수 Dart 클래스, 8번 테스트 전부 통과.
3. **조회 화면 – 메모 탭**: 필터 바, 필터 시트(태그·장소 선택 시트 포함), 안내 줄, 요약줄, 정렬, 메모 카드, 빈 상태.
4. **태그 통계 탭**: 카테고리 칩, 정렬, 계층 행과 펼침, 행 탭 시 필터 교체 + 메모 탭 이동.
5. **세션 상세 시트**.
6. **점검**: 1번의 조회 1~3을 웹에서 실제 데이터로 해 보고, 탭 전환 후 상태 유지, 일지 수정 후 조회 결과 갱신, 좁은 폭(약 400px)과 키보드 상황을 확인한다. 발견한 문제와 남은 한계를 정리해서 알려줄 것. 마지막으로 `CLAUDE.md`의 라우트 표(`/search`, 셸 구조), 폴더 구조(`data/repositories/search_repository.dart`, `domain/search/`, `ui/search/`), 구현 현황을 갱신한다.
