# 01. 일지 작성 MVP

공통 규칙, 기술 스택, 데이터 모델은 루트의 `CLAUDE.md`를 따른다. 이 문서는 이번 작업의 범위와 화면, 동작만 다룬다.

이번이 첫 기능 구현이므로 프로젝트 기반 작업(라우터, 테마, DB 초기화)도 포함한다.

## 1. 범위

**구현할 것**

- 프로젝트 기반: `riverpod_generator` 추가, 폴더 구조, go_router, 테마, drift DB(웹 설정 포함)
- `CLAUDE.md`의 데이터 모델 전체 테이블 생성
- 메인 화면 (일지 목록 + 진행 단계 표시 + 일지 삭제)
- 일지 작성 1단계: 세션 기본 정보 + 메모 입력
- 일지 작성 2단계: 메모별 태그·평가 확인
- 장소 등록 (작성 화면의 하단 시트)
- 지난 큐 불러오기
- 저장 시 자동 태그·평가 추천 (규칙 기반)
- 기본 태그 사전 시드 데이터

**구현하지 않을 것**

- 검색/조회, 통계 화면
- 태그 관리 페이지
- 레슨/연습 세션의 별도 입력 항목 (세션 유형 필드만 만든다. 유형에 따라 달라지는 건 스코어·큐 카드 노출 여부뿐)
- 사용자 수정으로부터 태그 사전 학습
- 메모 순서 변경(드래그)
- 장소 수정, 삭제

## 2. 메인 화면

일지 목록 + 진입점. 검색·필터·통계는 만들지 않는다.

- 하단에 고정된 **새 일지 쓰기** 버튼.
- **일지 목록**: 작성 중인 것과 저장을 끝낸 것을 **모두** 담고, 날짜가 최근인 것부터 보여준다.
  - 한 줄에 날짜(`26/9/22 금`), **진행 단계 배지**, 그 아래 보조 줄(`게임 · 귀뚜라미 실내 · 메모 3`).
  - 진행 단계 배지 3종:
    - **작성 중** — 1단계를 쓰다 말았다(status = draft).
    - **태그 확인 전** — 1단계 저장까지 끝났고(status = complete) 2단계가 남았다.
    - **확인 완료** — 2단계까지 끝났다(tagReviewed = true).
    - 확인 완료 뒤 1단계에서 메모를 **새로 쓰거나 고쳐서 다시 저장**하면 **태그 확인 전**으로 돌아간다. 다시 추천을 돌린 메모가 있으면 2단계를 다시 거쳐야 하기 때문이다. 메모를 지우거나 메모 외 항목만 바꾼 저장은 그대로 둔다.
  - 장소 이름은 **스냅샷을 먼저** 쓰고, 저장 전이라 스냅샷이 없으면 현재 장소 이름을 쓴다. 장소를 안 골랐으면 "장소 없음".
  - 줄을 탭하면 **1단계**(이어쓰기·수정), 줄 오른쪽 끝의 **태그 버튼**을 누르면 **2단계**로 바로 간다. 2단계를 보려고 매번 1단계를 새로 쓰지 않게 하려는 것이다.
  - **메모가 없는 일지에는 태그 버튼을 두지 않는다**(확인할 태그가 없다). 버튼 자리는 비워 둬서 줄 높이를 맞춘다.
  - 일지가 없으면 "아직 쓴 일지가 없어요." 문구만 보여준다.

**일지 삭제**

- 목록의 줄을 **좌우 어느 쪽으로 밀어도 삭제**된다. 목록 아래에 "밀어서 삭제" 안내를 작게 둔다(일지가 있을 때만).
- 지우면 **실행 취소 스낵바**를 **5초간** 띄운다. 되돌리면 그 일지의 게임·메모·메모 태그 연결까지 **원래 id와 순서 그대로** 복구한다. 되돌릴 길이 있으니 삭제 전에 따로 확인을 묻지 않는다(메모 삭제와 같은 방식).
- 장소와 큐는 일지가 **참조**하는 것이라 일지를 지워도 남는다. 게임·메모·메모 태그는 일지에 **딸린** 것이라 함께 사라진다(cascade).
- 일지 수정 화면(1단계)에서의 삭제는 두지 않는다. 메인 목록에서만 지운다.

## 3. 일지 작성 1단계

한 페이지 세로 스크롤. 관련된 항목은 **카드로 묶어** 보여준다. 위에서 아래 순서:

**상단 바**

- 뒤로가기(`<` 모양 하나만), 제목은 **화면 정보**("새 일지 작성" / "일지 수정", 굵고 또렷하게), 오른쪽에 자동 저장 상태 표시("자동 저장됨")

**세션 유형**

- 라벨 "세션 유형" + 분할 버튼: 게임 / 레슨 / **랠리 / 연습**. 기본값 게임. (DB 값 이름은 `practice` 그대로다 — 화면 표기만 바꾼 것이라 마이그레이션이 필요 없다.)
- 분할 버튼 모양:
  - 양 끝은 **알약처럼 둥글고**(양 끝 칸만 바깥쪽 모서리를 깎는다), 테두리는 두지 않는다.
  - 선택되지 않은 칸의 배경은 **카드보다 한 단계 옅은 면**, 글씨는 **흐린 회색**이라 선택된 칸이 먼저 읽힌다.
  - 선택된 칸은 **진한 파랑 채움 + 흰 글씨**이고 모서리를 깎지 않아 일자로 나뉘어 보인다.
  - 구분선은 **선택되지 않은 칸끼리 맞닿은 자리에만** 흰색으로 넣는다. 선택된 칸에 맞닿은 자리에는 선을 두지 않는다.
  - 둥근 정도는 "일지 저장" 버튼과 맞춘다.

**일시** (날짜와 시간을 한 카드에. 라벨 옆에 "시간을 누르면 휠 · ±는 10분" 보조 문구)

- 날짜: **입력칸처럼 보이는 블록 하나**로 둔다(면 + 테두리). 왼쪽에 고른 날짜를 `2026년 10월 9일 금요일` 형식으로, 오른쪽에 달력 아이콘(배경 없이 아이콘만). 본문보다 살짝 크고, 완전한 검정보다 한 톤 연하게.
- **블록 어디를 눌러도** 날짜 선택기가 열린다. 기본값 오늘.
- 시간: 시작, 종료 각각 `[−] 18:00 [+]` 형태. **± 버튼은 10분 단위** 조정.
- 시작·종료 줄은 **라벨이 왼쪽, 시간 칸이 오른쪽 정렬**. 라벨은 **날짜 표시와 같은 글자 스타일**을 쓴다.
- **± 버튼은 시간 칸의 양 끝을 채우는 캡**이다. 왼쪽 버튼은 왼쪽만, 오른쪽 버튼은 오른쪽만 둥글게 보인다(칸이 모서리를 깎아 낸다). 칸 가운데(값 부분)를 누르면 시간 시트가 열린다. **시간 칸에는 테두리를 두지 않는다.**
- "시간" 라벨과 작성 화면의 총 시간 표시는 두지 않는다(총 시간은 시간 시트에서만 보여준다).
- 시간 값을 탭하면 **하단 시트**가 열린다:
  - 시작과 종료 **휠 두 개를 나란히** 배치.
  - 각 휠은 **시간과 분이 한 줄로 합쳐진 단일 휠**이다: 06:00, 06:30, 07:00 … 24:00 (30분 단위).
  - 현재 값이 30분 단위가 아니면(예: ±로 만든 21:50), 휠 목록에서 21:30과 22:00 사이에 **21:50을 임시로 끼워** 보여주고 그 값이 선택된 상태로 연다. 가장 가까운 칸으로 바꾸지 않는다.
  - 휠 위에 **자주 쓴 시간** 칩 최대 3개(과거 세션에서 가장 많이 쓴 조합). 표기는 `18:00 - 20:00`. 탭하면 시작, 종료 동시 설정.
  - 시트 하단에 총 시간 표시(예: 3시간 50분)와 확인 버튼.
- 기본값: 가장 최근 세션의 시작, 종료 시간. 과거 세션이 없으면 18:00~20:00.
- **시작과 종료는 각각 따로 움직인다.** 한쪽을 바꿔도 다른 쪽은 그대로다.
- 종료가 시작보다 이르거나 같은 값은 **애초에 만들 수 없게 막는다**: ±는 시작 ≤ 종료−10분, 종료 ≥ 시작+10분에서 멈추고 그 자리에 이유를 짧게 보여준다. 시트에서는 확인 버튼을 막고 다시 고르게 한다. (과거 데이터가 어긋나 있으면 인라인 오류를 보여주고 저장 버튼을 막는다.)

**장소**

- 최근 사용 순 칩 최대 4개 + **더보기** 칩.
- 칩 아래에 선택한 장소의 정보를 작게 표시(예: "야외 · 하드").
- 등록 시트로 가는 **추가 버튼(＋ 아이콘)은 메모 추가 버튼과 같은 모양으로 카드 라벨 줄 오른쪽 끝**에 둔다. 누르면 등록 시트: 이름 입력, **"코트 표면"** 칩(하드/인조잔디/클레이/기타), 그 아래 **라벨 없이** 야외/실내 분할 버튼, 저장. 분할 버튼의 테두리는 **표면 칩의 테두리와 같은 색**으로 맞춘다. 저장하면 바로 선택된다. 같은 이름이 이미 있으면 이름 칸에 오류를 보여준다.
- **더보기** 탭 → 장소 선택 시트:
  - 상단 검색 입력. 비어 있으면 **이름 오름차순 전체**, 입력이 있으면 **이름에 그 말이 들어간 장소만** 남긴다.
  - 각 줄에 장소 이름과 정보("실내 · 하드"). 탭하면 선택되고 시트가 닫힌다.
  - **검색어와 정확히 같은 이름이 없으면 목록 맨 아래에 "'<검색어>' 새 장소로 추가"** 항목을 둔다. 탭하면 등록 시트가 **이름이 채워진 채로** 열리고, 저장하면 두 시트가 함께 닫히며 그 장소가 선택된다.

**컨디션**

- 분할 버튼 3칸: 별로 / 쏘쏘 / 굿. **모양은 세션 유형 분할 버튼과 같다.**
- **기본값 없음**(아무것도 선택 안 된 상태). 선택된 버튼을 다시 누르면 해제.

**마지막 식사** (라벨 옆에 "시작 기준" 보조 문구)

- 칩 4개: 1h 이내 / 1–2h / 2–3h / 3h+. 단일 선택, 다시 누르면 해제.

**큐** (세션 유형이 **레슨이 아닐 때만** 보인다)

- 한 줄 텍스트 입력.
- 입력칸 아래 왼쪽: **"지난 큐: (가장 최근 큐)"**, 탭하면 입력칸에 채움. 과거 큐가 없으면 숨김.
- 입력칸 아래 오른쪽: **지난 큐 불러오기** → 하단 시트:
  - 상단 검색 입력(부분 일치 필터).
  - 목록은 최근 사용 순. 각 줄에 큐 텍스트, 최근 사용 날짜, 사용 횟수, **최근 큐 적용 결과 배지**(됨/일부/안 됨, 색으로 구분. 기록 없으면 배지 없음).
  - 항목 탭 → 입력칸에 채우고 시트 닫힘.
- 저장 시 큐 텍스트를 정규화해서 **같은 텍스트의 큐가 있으면 그 큐를 재사용**하고, 없으면 새로 만든다.
- **큐 적용** 분할 버튼(됨 / 일부 / 안 됨, **모양은 세션 유형과 같다**)은 **큐 입력칸이 비어 있지 않을 때만** 표시. 아래에 보조 문구 "게임 중에 의식적으로 적용했나요?". 기본값 없음, 다시 누르면 해제.

**스코어** (세션 유형이 **게임일 때만** 보인다)

- 기록이 없으면 "스코어 기록 없음" 문구만 보여준다.
- 기록이 있으면 **경기 유형별로 묶어서** 보여준다. 유형 이름(예: "잡복")을 왼쪽에 쓰고, 그 오른쪽에 **스코어 값만**(예: "6 : 4", 모르면 "스코어 모름") 입력 순으로 늘어놓는다. 유형이 바뀌는 자리에 구분선을 둔다. 순서는 여복 → 남복 → 혼복 → 잡복 → 단식.
- 스코어 하나하나는 테두리 없는 칩이고, **이긴 경기만 연한 파란 면**(선택된 칩과 같은 색), 나머지는 흰 면이다. 스코어를 모르면 이긴 것으로 보지 않는다. 유형 이름은 조금 굵고 크게, 칩은 여유 있는 패딩으로 둔다.
- 추가·삭제로 들어가는 버튼은 **메모 추가 버튼과 같은 모양의 아이콘 버튼**(편집 아이콘)이고, **카드 라벨 줄 오른쪽 끝**에 둔다.
- 편집 버튼 → 하단 시트:
  - 지금까지 넣은 스코어를 **시트 안에서도 칩으로 보여준다.** 칩을 누르면(또는 칩의 x를 누르면) **바로 삭제**되고, 아래에 "누르면 삭제돼요" 안내를 둔다.
  - 형태 칩(여복/남복/혼복/잡복/단식), 나/상대 스코어 각각 −/+ 스테퍼(0부터 시작, "스코어 모름" 토글 시 스코어 null).
  - **추가** 버튼. 눌러도 **시트는 닫히지 않고** 목록에 바로 반영된다(한 세션에 여러 게임을 연달아 넣는다). 닫기 버튼은 두지 않고, 바깥을 눌러 닫는다.
- 스코어 수정은 두지 않는다. 지우고 다시 넣는다.

**메모**

- 라벨에 개수 표시(예: "메모 3").
- 메모 목록: 메모마다 **밝은 면을 깔아 블록으로** 구분한다(구분선·테두리 없음, 카드보다 조금 덜 둥글게).
- 줄을 탭하면 **수정 시트**(내용 입력 + 저장 + **삭제**). 좌우 어느 쪽으로 밀어도 삭제된다.
- 목록 아래에 "밀어서 삭제" 안내를 작게 둔다(메모가 있을 때만).
- 어느 쪽으로 지우든 **실행 취소 스낵바**를 **5초간** 띄우고, 되돌리면 태그 연결까지 그대로 복구한다.
- 목록 아래에 입력칸(폭 전체). 추가 버튼(+ 아이콘)은 **카드 라벨 줄 오른쪽 끝**에 둔다. **엔터 또는 추가 버튼 → 한 줄 추가 후 입력칸 비우고 포커스 유지.**
- **여러 줄을 붙여 넣으면 줄바꿈 기준으로 나눠서** 각각 메모로 추가(앞뒤 공백 제거, 빈 줄 무시).

**저장 버튼**

- 텍스트는 "일지 저장", 페이지 하단에 고정한다(스크롤과 함께 올라가지 않는다).
- **키보드가 올라와 있는 동안에는 숨긴다.** 키보드 바로 위에 붙어 있으면 글자를 누르려다 저장이 눌린다. 키보드를 내리면(빈 공간 탭, 키보드 내림 버튼) 다시 나타난다.

**입력 포커스**

- 입력칸 밖의 빈 공간을 누르면 포커스를 해제한다(키보드 내리기).
- 하단 시트나 선택기를 열기 전에도 포커스를 해제한다. 안 그러면 시트가 닫힐 때 직전 입력칸으로 포커스가 되돌아가 키보드가 다시 올라온다.
- 안드로이드의 **키보드 내림 버튼**으로 키보드가 닫히면 입력칸 포커스도 함께 푼다(커서만 남아 있지 않게).
- 검색이 있는 하단 시트(장소 선택, 지난 큐)는 **키보드가 올라오면 남는 높이에 맞춰 목록을 줄인다.** 고정 비율로 높이를 잡으면 화면을 넘쳐 overflow가 난다.

## 4. 자동 저장과 저장 규칙

- 페이지를 열기만 하고 아무것도 입력하지 않으면 DB에 기록을 만들지 않는다.
- 처음 값이 바뀌는 순간 draft 세션을 만들고, 이후 변경은 **짧은 지연(약 0.8초 디바운스) 후 자동 저장**. 필수값 검사 없이 저장한다.
- 페이지를 떠날 때 남은 변경이 있으면 즉시 저장.
- **저장 버튼**을 누르면:
  1. 필수값 검사: **날짜, 장소**. 없으면 해당 항목에 인라인 오류를 보여주고 그 위치로 스크롤.
  2. 장소 스냅샷 값(이름, 표면, 실내외)을 세션에 복사.
  3. 메모가 1개 이상이면 status = complete, 없으면 draft 유지.
  4. **자동 태그·평가 추천 실행** (6번 참고). 다시 추천을 돌린 메모가 하나라도 있으면 tagReviewed = false로 되돌린다.
  5. 하단 시트 표시: "저장했어요. 추천 태그 N개" + 버튼 **태그 확인하기**(→ 2단계) / **나중에**(→ 메인). 메모가 없으면 시트 없이 메인으로.

## 5. 일지 작성 2단계 (태그·평가 확인)

- 상단 바: 뒤로가기, 제목 "태그 확인", 오른쪽 **모두 확인**.
- 메모마다 카드 하나:
  - 메모 내용
  - 태그 칩들: **confirmed는 실선 채움, suggested는 점선 테두리**. suggested 탭 → confirmed. 칩의 x → rejected(화면에서 사라짐).
  - **`＋ 태그 추가` 칩** → 하단 시트: 태그 검색 입력, 입력할수록 **자동완성 목록**이 입력칸 아래에 표시. 목록에서 선택하면 manual/confirmed로 추가. 일치하는 태그가 없으면 **"'입력값' 새 태그 만들기"** 항목 → 카테고리 선택 후 생성하고 바로 추가.
    - **아이콘만 두지 않고 글자를 함께 쓴다.** 태그가 하나도 붙지 않은 메모에서는 이 칩만 홀로 남는데, `＋`만 있으면 무엇을 더하는 버튼인지 바로 읽히지 않는다.
  - **둥근 정도와 크기는 한곳에서만 정한다**(`ChipMetrics`). 각 위젯이 안쪽 여백으로 높이를 만들면 글자와 아이콘 크기 차이 때문에 몇 px씩 어긋나 보인다.
    - **태그 칩과 `＋ 태그 추가` 칩은 높이가 같다.** 글자 크기를 키운 기기에서 잘리지 않게 **고정이 아니라 최소**로 둔다.
    - **평가 버튼은 가로로 넓고, 칩보다 조금 높다.** 아이콘을 정사각형 안에 넣으면 위아래 여백이 좌우와 같아져서 버튼이 뭉툭하게 솟아 보이므로 좌우를 더 벌린다. 칩은 글자가 안을 채우지만 평가 버튼은 아이콘 하나뿐이라, 높이까지 칩과 똑같이 맞추면 오히려 작아 보인다.
    - 평가 아이콘 글리프는 버튼 높이의 **2/3쯤**으로 둔다. 위아래 여백이 좌우보다 좁아야 비율이 맞아 보인다.
  - **평가 버튼은 보이는 크기와 터치 영역을 따로 잡는다.** 손가락이 닿는 영역은 보이는 네모보다 큰 **48dp**다. 탭은 48dp 쪽이 받는다 — 보이는 네모 안에 두면 터치 영역도 같이 줄어든다. 버튼 사이 간격은 따로 주지 않는다: 48dp 안에서 네모가 가운데 놓이며 남는 여백이 간격이 된다.
  - 평가 아이콘 3개: 잘함 👍 good / 못함 👎 bad / 물음표 ❓ question. 하나만 선택, 다시 누르면 해제.
  - **아이콘은 Material 아이콘을 쓴다. 이모지는 쓰지 않는다.** 색 이모지는 글자색으로 물들일 수 없어서 선택 강조가 안 되고, 웹(CanvasKit)에서는 이모지 대체 글꼴을 실행 중에 내려받아야 해서 오프라인이면 빈칸으로 나온다. 기기·플랫폼마다 그림도 달라진다.
  - 버튼은 **네모 모양**이고, **둥근 정도는 태그 칩과 같은 값**을 쓴다.
  - 아이콘 하나가 가지는 모습은 **세 가지**다. 면은 **고르지 않음과 추천이 모두 흰색**이고 둘은 테두리로만 갈린다:
    - **고르지 않음** — `＋` 태그 칩과 **같은 실선 테두리 + 흰 면**. 아이콘은 윤곽선 모양, 흐린 회색.
    - **추천(suggested)** — **점선 테두리 + 흰 면.** 아이콘은 채운 모양에 해당 색(초록/빨강/파랑 계열).
    - **확정(confirmed)** — **테두리 없이 색 면만** 채운다. 아이콘은 채운 모양에 해당 색.
  - 추천 아이콘을 탭하면 confirmed, 다른 아이콘을 탭하면 그 평가로 바뀌며 confirmed, 확정된 것을 다시 탭하면 평가 없음. (추천을 탭한 것은 "확정"이라 해제가 아니다.)
- **모두 확인**은 suggested 태그와 suggested 평가를 모두 confirmed로 바꾼다.
- 안내 문구: "추천 태그/평가는 점선으로 표시돼요. 터치하면 태그/평가가 확정돼요."
- 하단 **완료** 버튼 → tagReviewed = true, 메인으로.
- 변경 사항은 즉시 DB에 반영한다.

## 6. 자동 태그·평가 추천 (규칙 기반)

UI와 분리된 **순수 Dart 클래스**로 만들고 단위 테스트를 작성한다. 입력: 메모 텍스트 + 태그 사전(태그, 인식 표현, 제외 단어). 출력: 붙일 태그 id 목록과 각 태그의 확실/애매 여부, 추천 평가(없으면 null).

**태그 알고리즘**

1. 메모 텍스트 정규화(소문자, 연속 공백 하나로).
2. 모든 인식 표현을 **긴 것부터** 검사한다. 텍스트 원본과 **공백을 모두 뺀 버전** 양쪽에서 찾는다(예: "포 스트로크"와 "포스트로크"를 같게 인식).
3. 매칭된 구간은 **표시해 두고, 이후 더 짧은 표현이 그 구간 안에서 다시 매칭되지 않게** 한다. 예: "백발리"가 매칭되면 그 안의 "백"이나 "발리"로 다른 태그를 또 붙이지 않는다.
   3-1. 단, **완전히 같은 인식 표현이 여러 태그에 등록돼 있으면** 그 구간은 해당 태그 모두가 함께 사용한다(모두 붙인다). 예: "스핀서브"가 #킥과 #서브에 모두 등록돼 있으면 둘 다 붙인다.
4. 매칭된 구간이 해당 태그의 **제외 단어** 출현 범위와 **겹치면** 무시한다(일부만 겹쳐도 무시).
   예: #서브의 제외 단어 "서브 리턴", "서브 리시브" → "스핀서브 리턴 어렵다"에서 "스핀서브"는 "서브 리턴"과
   일부만 겹치지만 #서브를 붙이지 않는다. 제외는 **태그별**이라, 같은 구간을 쓰는 #킥은 제외 단어가 없어서 그대로 붙는다.
5. 인식 표현의 confidence가 sure면 status = confirmed, ambiguous면 suggested. source는 auto.
6. 자식 태그가 매칭되면 자식만 붙인다(부모는 조회 시 포함).

**평가 추천**: 아래 키워드만 사용한다(태그 사전처럼 DB에 두지 않고 상수로 정의).

| 평가     | 키워드                    |
| -------- | ------------------------- |
| good     | 짱, 굿, 개굿, 잘 됨, 잘됨 |
| bad      | 안됨, 안 됨, ㅠ, ㅠㅠ     |
| question | ?                         |

- 키워드가 메모 어디에든 **포함**되면 매칭으로 본다.
- 여러 평가가 동시에 매칭되면: **question이 있으면 question**을 추천한다. question 없이 **good과 bad가 둘 다 매칭되면 추천하지 않는다**(판단 보류).
- 추천 결과는 evaluation에 넣고 evaluationStatus = suggested.

**저장 시 적용 규칙**

- 내용이 lastTaggedContent와 다른 메모만 다시 처리한다.
- **manual 태그와 rejected 태그는 건드리지 않는다.** rejected인 태그는 다시 매칭돼도 붙이지 않는다.
- 내용이 바뀐 메모의 기존 auto 태그 중 새 결과에 없는 것은 제거한다.
- **evaluationStatus가 confirmed인 평가는 절대 덮어쓰지 않는다.** 평가가 비어 있거나 suggested인 메모만, 내용이 바뀌었을 때 새 추천 결과로 교체한다(추천 결과가 없으면 비운다).

**단위 테스트** (최소한 다음은 통과해야 함)

| 메모                                               | 기대 결과                                    |
| -------------------------------------------------- | -------------------------------------------- |
| 포인트 몇 개 땀                                    | #포핸드 없음                                 |
| 서브 더플폴트 3연속                                | #서브, #더블폴트                             |

## 8. 구현 단계

1. **프로젝트 기반**: `riverpod_generator` 추가, 폴더 구조, go_router 설정, 테마, 빈 메인 화면. 웹과 Android에서 실행 확인.
2. **데이터 계층**: `CLAUDE.md`의 데이터 모델대로 drift 테이블 생성, DB 초기화(웹 설정 포함), 시드 데이터, 리포지토리. 웹에서 DB가 생성되고 새로고침 후에도 유지되는지 확인. 웹 설정에 내가 해야 할 수동 작업이 있으면 알려줄 것.
3. **자동 태그·평가 추천 엔진**: 순수 Dart 클래스 + 6번의 단위 테스트 전부 통과.
4. **1단계 화면**: 3번의 모든 항목과 하단 시트들, 4번의 자동 저장과 저장 규칙.
5. **2단계 화면**: 5번 전체.
6. **메인 화면 연결**: 새 일지, 일지 목록(진행 단계 배지, 1·2단계 바로가기), 밀어서 삭제 + 실행 취소.
7. **점검**: 전체 흐름(새 일지 → 메모 입력 → 저장 → 태그 확인 → 메인 → 이어쓰기)을 웹에서 확인하고, 발견한 문제와 남은 한계를 정리해서 알려줄 것. 마지막으로 `CLAUDE.md`의 구현 현황을 "완료"로 갱신.
